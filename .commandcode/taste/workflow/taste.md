# Workflow

- When asked to build a design/UI, wants the visual design delivered as pure static markup — strips out client-side interactivity and runtime "logic" (useState, handlers, fake data states) rather than shipping interactive machinery. Confidence: 0.65
- Communicates frustration bluntly when work drifts from the ask (e.g. "i want the design not fucking logics"); prioritize delivering exactly what was requested over adding unrequested functionality. Confidence: 0.5
- Expects UI work to reflect the product's real domain and user roles (e.g. customer-facing booking + admin/dispatch views); issues corrective feedback when the agent builds a generic industry archetype instead of matching the actual product. Confidence: 0.5
- Wants UI copy/content localized to the product's real market (Bangladesh) — local areas/districts (Gulshan, Banani, Dhanmondi), ৳ BDT pricing, +880 phone numbers, bKash payouts, and local names — instead of generic placeholder content. Confidence: 0.55
- Prefers new pages/components to mirror the structure, state pattern, and styling of existing analogous pages in the codebase (e.g. "look at the login page now make like this for register page") — consistency with established conventions over inventing a fresh layout. Confidence: 0.6
- When asking to "design" a page that already exists functionally, means restyle it onto the app's established visual system (tokens, typography, shared shells) scoped to the UI — underlying business logic/API calls stay intact. Confidence: 0.6
- Prefers repeated UI patterns extracted into shared, reusable components (layout shell, labeled text field) so sibling pages stay visually consistent instead of duplicating markup. Confidence: 0.55
- When reporting a runtime error (e.g. an HTTP 500 on an API route), wants a direct root-cause answer plus the fix actually applied and demonstrated in the terminal (real commands run to reproduce/verify), not a prose-only walkthrough. Confidence: 0.55
- Asks for terse responses on focused questions ("just answer this") — answer the specific question rather than expanding into a broad explanation or unrelated changes. Confidence: 0.5
- Just do the task directly, not unusual/ad-hoc shell work ("just do the task dont ususual shell work", "finish it quickly no unsual shell task", "stop unusual shell task just solve issue") — prefer the standard, obvious path and avoid extra exotic one-off commands or meandering shell exploration. Confidence: 0.7
- Expects tasks driven to full completion ("finish the task solve all error") — resolve every outstanding error and reach a verified working state before stopping, rather than reporting partial progress or handing back a task with known failures. Confidence: 0.55
- Reports problems by pasting raw terminal output verbatim (command + full error text, sometimes with IDE file/line context) instead of describing the issue in prose — expect to parse the raw log to identify the failing step. Confidence: 0.5
