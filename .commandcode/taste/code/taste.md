# Code style

- Prefers client forms built with react-hook-form (register/handleSubmit/useWatch) rather than hand-rolled useState form state. Confidence: 0.6
- Wants easy-to-read, straightforward code and explicitly rejects hardcoding ("do easy readable code not hard code") — prefer clear, obvious implementations over clever/terse ones, and drive values/logic from real data sources rather than hardcoded literals. Confidence: 0.6
- Wants page/component markup kept minimal and clean — little styling noise, no verbose multi-class strings or wrapper/helper components just for layout ("easy code no messy class or code"). Explicitly wants styling done with plain Tailwind utility classes rather than a complex/over-abstracted design system ("dont change or make it complex code design like tailwind class based"). Simpler markup beats an elaborate visual treatment when the user says "easy". Confidence: 0.7
- Prefers server and client code split into separate files rather than mixed in one file — a Next.js route should have a server `page.tsx` (auth check + `redirect`) and a co-located `"use client"` form component in its own file ("rather create a new page for individual separate server and client"). Avoid stuffing server-only code or an async component into a client file. Confidence: 0.6
- For address/location inputs, drive the fields from the Bangladesh location data: cascading district → upazila `<select>`s (changing district clears the upazila) with the street address as a free-typed input. Confidence: 0.5
